Algoritmo de distribuição

  1. Soma de SCT ativa por fiscal primário (Liza, Thiago, Lucas) — exclui processos em status bloqueado externo, aprovado em trâmite, concluído e arquivado.
  2. Atribui ao fiscal com menor Σ SCT.
  3. Empate → desempate por rotação: vence quem recebeu o último processo há mais tempo (ou nunca recebeu).
  4. Se todos os primários ≥ limiar (configurável, padrão 12 SCT) → Matheus entra como suplente de elaboração.
  5. Completo / Apenas TR: elaboração → revisão Matheus → aprovação Kerolaine → aprovado em trâmite → concluído.
  6. Aditivo / Apostilamento: elaboração → concluído. Fluxo direto — servidor designado é responsável integral.

ConcluídoObjeto plenamente atingido: contrato firmado, ARP publicada, OS emitida, inexigibilidade efetivada.Apenas editando manualmente.
ArquivadoEncerramento sem conclusão normal: perda de objeto, oportunidade fracassada, sobrestamento permanente, cancelamento.Sim — via "Desarquivar". Permite escolher para qual status retornar.
Ressalvas operacionais: a planilha histórica registra resultado, não carga real — o sistema só reflete a realidade se alimentado prospectivamente. A pontuação dos processos pré-existentes é estimativa: revise os scores antes de operar produtivamente. O gargalo de aprovação exclusiva da coordenadoria é tornado visível pelo SLA, mas não resolvido pelo sistema. localStorage é por navegador — para uso concorrente em rede é necessário backend (Sheets API, SQLite+servidor, Airtable, Notion).

Parâmetros do algoritmo

Fiscais primários (pool de elaboração)

A ordem é usada apenas como segundo desempate, depois da rotação por timestamp. Padrão: alfabético.

    Prioridade de Matheus

    Quando Matheus está em modo suplente de elaboração e existe TR na sua fila de revisão com SLA ≥ 2 dias, o sistema sinaliza que a revisão tem prioridade. A regra é informativa — não bloqueia ações.
